# Commercial readiness

Grab the Crab 0.2.0 is prepared for a buyer's **technical evaluation and acquisition discussions**. A buyer can inspect the code, install the evaluation interface, reproduce the current simulated audit and review the delivery scope. This document records readiness; it is not an offer, license grant, purchase agreement or representation of sole ownership.

## Proposed transaction scope

The working assumption for this preparation is a transfer of the project code and its documented technical assets. The buyer, price, transfer structure, exclusivity, support obligations and completion date have not been specified. These remain negotiable. A commercial license or paid field pilot can use the same technical package with a different signed scope.

Include the source, packaged evaluation assets, UI/API, inference/planner implementation, training code, test suite and documentation, subject to verified rights. List trained weights separately if the team supplies them; none are currently included. External datasets, open-source dependencies and map providers retain their own terms. Do not promise exclusive ownership of those materials.

## Before contractual closing

1. Confirm all contributors and other parties with rights; obtain signed authority for the agreed transfer from each necessary rights holder. Repository admin permission is not evidence of sole copyright ownership.
2. Inventory every delivered asset and its exact revision. Resolve the source obligations in the rights register and preserve third-party notices.
3. Decide whether trained checkpoints are part of the sale. Transfer the actual files and evidence if promised.
4. Define the buyer's acceptance checks and sign the transaction scope, payment terms and transition responsibilities.
5. Decide repository visibility, buyer access and any transfer of repository control explicitly. This preparation does not change visibility or transfer the repository.

The repository is public. Existing viewers, forks and downloaded copies must be considered in any exclusivity discussion; changing visibility does not retrieve copies already made. [GitHub's licensing guidance](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/licensing-a-repository) explains the relationship between licensing and public repository access.

Use the buyer brief for presentation. Keep negotiated price, draft agreements, identities, credentials and signed assignments in a private transaction location, not in this public repository.
